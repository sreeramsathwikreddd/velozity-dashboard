The hardest problem was the role-filtered real-time feed: three roles need three different slices of the same event stream, and it had to be impossible to get this wrong by forgetting a frontend check. I solved it by pushing the filtering into Socket.io room membership rather than into what the client does with incoming events. Each task-status change is emitted once, to a fixed set of rooms computed server-side: "global" (admin), the owning project's room (its PM), and the assignee's personal room (that developer). A developer's socket never joins a project room in the first place — there's no room for it to be routed to something wasn't allowed to see. Room joins are re-validated against the database on every request, never trusted from the client. The same scoping logic backs the missed-event catch-up endpoint, so a user coming back online gets an identical view from Postgres instead of a separate, possibly-inconsistent code path.

If I did it differently, I'd add a Redis adapter for Socket.io from the start. The current room-based design assumes one server process; it's correct but won't broadcast across instances the moment this runs behind a load balancer, and retrofitting that later touches every emit call rather than just the transport layer.
